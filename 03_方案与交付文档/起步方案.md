# 智慧校园综合管理平台 · 项目三起步方案（六人版）

> 项目三（PC 端，中高难度，6 角色）｜6 人小组｜周期 1.5 周
> 面向组长：先读「一、结论」，再按「五、推进节奏」在组会上直接分工。
> 依据材料：`01_项目文档与任务书/项目选题.pdf`、两张分工截图，以及《页面分工与拓展页方案.docx》（该文件未入库，结论已并入本文 §3.2、§3.3）。

## 一、结论：先做三件事

1. **定 13 页清单和路由表**（PDF 的 10 页 + docx 的 2 个拓展页 + 六人版的图书借阅页），当场认领，每人写进 README。
2. **用现成骨架跑起来**：`02_程序源码/frontend/index.html` 双击即开，`02_程序源码/server/app.js` 提供同一套假数据接口，组员不用等环境。
3. **按页面分工并行开发**：吴 / 万 / 任 / 王 / 石 / 高，每人 2–3 页；公共文件由万统一改。

骨架现状（已可运行）：

- 13 个页面全部有文件、可点通，空状态和假数据齐全；
- 6 个角色、登录、路由守卫、菜单过滤、按钮权限已跑通；
- 前端零构建（依赖在 `vendor/`），后端零依赖（`node server/app.js`），不需要 `npm install`；
- 数据层双模式：有接口走 HTTP，没有就回落 localStorage。

## 二、任务书硬性要求拆解

### 2.1 原文要求 vs 本组落地

| 要求 | 任务书原文要点 | 本组落地 |
|---|---|---|
| 角色 | 管理员、教务管理员、辅导员、教师、学生（PDF 5 个）+ 图书管理员（六人版新增） | 权限矩阵按 6 角色设计；图书管理员已在骨架落地 |

### 2.3 一票否决项

- 换掉 Vue2 全家桶（React / Vue3 都不行）；
- 核心页面少于 10 个，或有人少于 2 页；
- 只有静态页面，增删改查点不通；
- 没有权限控制，任何角色都能进任何页面。

### 3.3 六人版为最终基准，5 人版作为缩减方案

材料里存在两套分工口径，**现已确认采用第二张截图的六人版**：

- **六人版（最终基准）**：吴（学生信息 + 课程排课）、万（登录角色 + 数据总览 + 消息中心）、任（考试考务 + 学工请假）、王（图书借阅 + 校园场馆预约）、石（选课 + 成绩）、高（教师工作台 + 学生端门户）。
- **5 人版（缩减方案，仅在人数不足时启用）**：沿用 PDF 的 A–E 分工，去掉图书借阅页与图书管理员角色，王原负责的两页并入 E；其余页面不变，总页数降为 12。

六人版新增的「图书借阅」不是加一个空页面，而是**完整的第三条业务线**（馆藏 → 借阅 → 归还/续借 → 逾期），对应骨架里已经落地的三处改动：

1. **`js/auth.js` 的 `ROLES`**：新增 `librarian`（图书管理员），首页 `/campus/library`；登录页角色卡由 5 张变 6 张，自动读取该配置，无需改登录页代码。
2. **`js/auth.js` 的 `PERMISSIONS`**：`librarian` 拥有 `book:add / book:edit / book:borrow / book:return / book:renew / venue:approve / message:publish`；学生、教师补充借还权限；教务、辅导员没有图书权限。
3. **`js/router.js` 的路由 `meta.roles`**：`/campus/library` 放行 `admin / librarian / teacher / student`，教务与辅导员访问会被守卫拦到 403；同时 `ALL` 加入 `librarian`，场地预约、消息中心对新角色同样可用。

联调依赖：

- **成绩页依赖上游数据**：石的成绩页依赖吴的课程学分与教学班，联调顺序必须是吴 → 石。
- **门户页最后做**：高的教师工作台/学生门户是全员数据的出口，排在 D7 之后联调，避免反复改。
- **图书借阅依赖读者数据**：借阅记录的 `userId/userName` 直接取登录态，无需等学生信息页；馆藏数据由王在 `seed.js` 的 `books/borrows` 维护。

## 四、技术选型与默认假设

### 4.1 选型表

| 层 | 选型 | 理由 |

| 视图 | Vue 2.7 + Vue Router 3 + Vuex 3 | 任务书指定，组件生态成熟 |

| 数据 | `seed.js` + localStorage / JSON 文件 | 前后端共用同一份假数据，规则集中 |

### 4.2 双模式数据层

- 页面只调 `api.js`，不直接碰 axios 或 localStorage；
- `api.js` 探测 `/api/health`：成功走 HTTP（顶栏显示「接口模式」），失败回落 localStorage（「本地 Mock」）；
- 支持 `?api=local` / `?api=remote` 强制切换，方便排查；
- 本地模式写入浏览器缓存，演示前可在头像菜单「重置演示数据」。

### 4.3 默认假设（信息不足时按此推进）

1. **小组按 6 人计**（已确认）：六人版是最终基准，图书管理员与图书借阅页已在骨架落地；若临时减到 5 人，按 §3.3 的缩减方案去掉该角色与页面即可。
2. **后端允许 Mock**：任务书允许纯前端 + 假数据，本项目用 Node Mock 提供同构接口，答辩时说明"将来替换真实后端不改页面"。
3. **图片/附件走本地或占位**：不做真实对象存储，上传只做前端校验与预览。
4. **字段契约以 `seed.js` 为准**：D2 晚冻结，之后改字段必须全员同步。

## 八、答辩准备

### 8.1 5 分钟演示顺序

1. 学生登录 → 门户看课表/成绩 → 选课 → 预约场地（提交成功，提示待审批）。
2. 管理员登录 → 场地审批通过 → 消息中心看到审批通知、铃铛角标。
3. 教师登录 → 工作台看课表 → 成绩录入/批量保存 → 加权统计与补考名单。
4. 图书管理员登录 → 图书借阅检索/只看可借 → 借阅 → 续借（限 1 次）→ 归还；逾期记录标红。
5. 教务登录 → 学生管理增删改查 + 照片上传 → 排课冲突检测。
6. 学生直接输入 `/#/exams`、教务输入 `/#/campus/library` → 被守卫拦到 403（讲权限设计）。

### 8.2 预设问题

1. **权限怎么做？** 路由 `meta.roles` + 菜单过滤 + 按钮 `v-perm`，权限集中在 `auth.js`。
2. **排课冲突怎么判？** 同教师/同教室/同时间重叠即冲突，保存前校验并给出具体冲突项。
3. **预约冲突怎么判？** 同场地、同日期、时间段重叠；返回 409 并提示可用时段。
4. **消息已读怎么实现？** `messages` + `receipts`，未读数 = 目标角色消息数 − 已读回执数。
5. **为什么不用真实后端？** 任务书允许 Mock；接口层已抽象，换后端只改 `api.js` 的 baseURL。
6. **成绩加权怎么算？** 总评 = 平时 40% + 期末 60%；加权平均 = Σ(总评×学分)/Σ学分；总评 < 60 进补考名单。
7. **图书借阅的规则在哪校验？** 可借数量、单人上限 3 本、同书未还不可重复借、借期 30 天、限续借 1 次，全部在 `core.js` 的 `borrowBook/returnBook/renewBorrow` 校验，页面只负责提示；逾期由应还日期与当前日期比较得出。
8. **为什么用 Vue2？** 任务书指定；团队熟悉，Element UI 与管理后台场景匹配。
